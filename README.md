# Godot C# Game Setup

A Claude skill that turns "let's make a game" into a strictly managed Godot 4 (.NET) repository: design docs, a
phased plan, recorded decisions, and a project scaffold where formatting, docs, tests, localization, content
validation and allocation budgets are enforced by tools from the first commit.

It works for any genre. It decides tooling, structure and quality gates, and leaves gameplay architecture to each
game's own design docs and decision records. Everything in it was distilled from a real Godot .NET game built with
Claude over several phases, and the scaffold is verified end to end.

## What it does

When you ask Claude to start, plan or scaffold a Godot C# game, the skill guides it through:

1. **A short interview** covering only what can't be defaulted: title, Godot version, code host (GitHub or GitLab),
   languages, 2D or 3D, renderer.
2. **A toolchain check** for a matching .NET SDK and Godot .NET editor.
3. **The scaffold**: a complete repository generated by `scripts/scaffold.py`.
4. **Verification**: every quality gate run green, then broken once on purpose to prove it's wired in.
5. **Design docs** filled in for the game: a GDD with a binding lexicon, art direction with performance budgets, a
   phased implementation plan, and architecture decision records.
6. **A hand-off** of the steps that need your accounts: the remote, branch protection, Pages.

## What the scaffold gives you

### Architecture

- An engine-free `Core` library for game rules, unit-tested, with a thin Godot layer that only presents it.
- A composition root with explicit dependency injection: no mutable statics and no service locator.
- Deterministic, seeded random streams (xoshiro256\*\*), with time behind an injectable clock.

### Quality gates

- Warnings as errors, with .NET analyzers, StyleCop, Roslynator and banned APIs (no `System.Random`, wall clock,
  `GD.Print` and similar).
- XML docs required on every member, CSharpier formatting, and exact SDK pins in `global.json` and CI.
- xUnit v3 Core tests with an 85% line-coverage gate.
- File-based tests of `project.godot`, scenes, PO catalogs and content, which run in milliseconds without the engine.
- An in-repo Godot runtime test runner that fails on any engine error and checks for zero managed allocations per
  frame.

### Content and localization

- Data-driven content as JSON in registered kinds, with permanent IDs and generated JSON Schemas.
- Key-based gettext PO localization from day one, with fuzzy catalogs for every extra locale.

### CI and docs

- GitHub Actions or GitLab CI: format, Debug and release builds, Core tests with coverage, a headless Godot smoke
  test, and the wiki.
- A developer wiki generated from the code with DocFX and published to Pages.
- A pre-commit hook and Git LFS set up for art and audio.
- Ready-to-fill `CLAUDE.md`, coding standards, GDD, art direction, implementation plan and ADRs 0001 to 0009.

## Using it

### With Claude

Add the skill to Claude, then ask for what you want, for example "Let's start a new 3D Godot C# game" or "Set up a
strict Godot .NET repo for my game". Claude runs the interview, the scaffold, the verification and the docs.

### Running the scaffold yourself

```bash
python scripts/scaffold.py --name MyAwesomeGame --title "My Awesome Game" --dest ../my-awesome-game \
  --godot 4.5.1-stable --locales en,es,de --ci github --renderer forward_plus
```

| Option | Meaning |
| --- | --- |
| `--name` | PascalCase identifier for the assembly and namespaces (required) |
| `--dest` | Target folder: empty, or holding only `.git` (required) |
| `--godot` | A `godotengine/godot-builds` release tag, such as `4.5.1-stable` or `4.8-beta1` (required) |
| `--title` | Display title (default: the name) |
| `--locales` | Comma-separated locale codes, `en` first (default: `en`) |
| `--ci` | `github`, `gitlab` or `none` |
| `--renderer` | `forward_plus`, `mobile` or `gl_compatibility` |
| `--dotnet-sdk` | Exact SDK for `global.json` and CI (default: the newest installed match) |
| `--overwrite` | Allow a non-empty folder: same-named files are replaced and listed, everything else is kept |
| `--skip-dotnet` | Skip creating the solution, restoring tools and formatting |

An empty folder is recommended. For a project you already created in the Godot editor, commit it, run with
`--overwrite`, then review `git diff` and merge your settings back into `project.godot`.

### Requirements

- Python 3 (standard library only).
- A .NET SDK whose major version matches the target framework (default `net10.0`).
- The Godot .NET editor, 4.5 or later, matching `--godot`.

## Repository layout

```txt
SKILL.md              The skill's instructions for Claude
references/           Planning, adapting, verification, wiki and lessons-learned guides
scripts/scaffold.py   The scaffold generator
templates/project/    The project template (dotfiles stored as _dot_<name>)
templates/MANIFEST.txt  Every template file, checked before each scaffold
```

## Maintaining the skill

- **Template files never start with a dot.** Skill uploads drop dot-prefixed paths, so they are stored as
  `_dot_<name>` (folders too) and the scaffold restores the dot.
- After adding or removing a template file, run `python scripts/scaffold.py --update-manifest`.
- Before every upload, run `python scripts/scaffold.py --check-template`.
- After bumping Godot, the SDK or a package, scaffold a throwaway project and rerun
  [references/verification.md](references/verification.md).

The verified version combinations are listed at the end of [SKILL.md](SKILL.md).
